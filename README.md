# Бриф на ведение соцсетей

Статический сайт: HTML + CSS + JS, без фреймворков и сборки. Лежит на GitHub Pages.
Ответы уходят в Telegram сообщениями через Cloudflare Worker. Пока Worker не подключён, форма предлагает скачать файл с ответами.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | разметка: интро, контейнер этапов, финал, подвал |
| `styles.css` | оформление (палитра, шрифты, адаптив) |
| `app.js` | вопросы массивом `STAGES` в начале файла, ссылки `SITE`, логика |
| `config.js` | только адрес приёмника (Worker) |
| `legal.js` | тексты Datenschutzerklärung и Impressum для окна в форме |
| `worker.js` | код для Cloudflare, на сайте не используется |
| `fonts/`, `assets/` | шрифты Actay Wide и Cygre, логотипы |

## Что осталось заменить перед публикацией

Всё в начале `app.js`, в объекте `SITE`:

1. `telegram` — ссылка на ваш Telegram, уже стоит `https://t.me/growth_house`. Кнопка «Написать в Telegram» на финальном экране берёт её отсюда.
2. `replyDays` — через сколько рабочих дней вы отвечаете (по умолчанию 2).
3. `photoIntro`, `photoDone` — фото на первом и финальном экранах (`assets/photo-intro.png`, `assets/photo-final.webp`, скачаны с 1225digitaldesign.de). Чтобы поменять, положите другой файл в `assets` и поправьте путь.
4. Подпись под фото на интро (имя и роль) — в `index.html`, блок `<figcaption>`.
5. Документы в подвале (Datenschutz и Impressum) открываются окном внутри формы, клиент не уходит на основной сайт. Тексты лежат в `legal.js` (взяты с 1225digitaldesign.de дословно, Datenschutzerklärung от мая 2026). Когда меняете документ на основном сайте, обновите и `legal.js`. Тексты юридические: править их лучше с юристом. В подвале остались телефон и email (блок `<address class="foot__contacts">` в `index.html`), почтового адреса там нет.

Подвал показывается только на последнем этапе («Связь») и на финальном экране.

## Подключение бота и Worker

### 1. Бот
1. В Telegram откройте [@BotFather](https://t.me/BotFather), команда `/newbot`, получите **токен**.
2. Напишите своему боту любое сообщение (или добавьте его в группу и напишите там).
3. Узнайте **chat id**: откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найдите `"chat":{"id": ...}`. Для группы id начинается с `-`.

### 2. Worker
1. [dash.cloudflare.com](https://dash.cloudflare.com) → Workers & Pages → Create → Create Worker.
2. Вставьте содержимое `worker.js`, нажмите Deploy.
3. Settings → Variables and Secrets, добавьте:
   - `BOT_TOKEN` (Secret) — токен бота;
   - `CHAT_ID` (Secret) — chat id;
   - `ALLOWED_ORIGIN` (Text) — адрес сайта без слэша на конце, например `https://имя.github.io`. Тогда Worker примет запросы только с вашего сайта;
   - `THREAD_ID` (необязательно) — id темы, если пишете в группу с темами.
4. Скопируйте адрес Worker (`https://…workers.dev`).

### 3. Сайт
Вставьте адрес в `config.js`:

```js
window.BRIEF_CONFIG = { endpoint: "https://brief.ваш-аккаунт.workers.dev" };
```

Токен бота на сайте нигде не хранится, он только в Worker.

### Как приходят ответы
- Первое сообщение — сводка: имя, контакты, главное по делу.
- Дальше каждый этап отдельным сообщением, вопросы жирным.
- Пустые вопросы не показываются.
- Длинные ответы режутся по абзацам, потом по предложениям и словам, чтобы уложиться в лимит Telegram (4096 знаков).
- Файлы приходят следом отдельными документами (до 18 МБ каждый), в тексте ответов они не перечисляются.

### Если отправка не удалась
Ответы не теряются: сайт скачивает `.txt` с ответами, показывает их текстом для копирования. Ответы остаются на странице, пока она открыта. Черновик в браузере не сохраняется: форма всегда открывается пустой. Клиенту предлагается прислать файл вам в Telegram.

## Как менять вопросы

В `app.js` массив `STAGES`: этапы, внутри массив `questions`. Поля вопроса:

| Поле | Значение |
|---|---|
| `id` | уникальный id |
| `key` | ключ ответа (используется в черновике, Telegram, файле) |
| `label` | текст вопроса |
| `hint` | пояснение под вопросом (необязательно) |
| `required` | `true` — обязательный, без ответа дальше не пустит |
| `star` | `true` — плашка «важно» |
| `type` | `long` (по умолчанию), `short`, `email`, `tel`, `checks`, `links`, `files`, `consent` |
| `options` | варианты для `checks` |
| `rows` | минимальная высота поля в строках |

Чтобы поменять число этапов, добавьте или уберите объект в `STAGES`: прогресс, точки и счётчик «01 / 09» пересчитаются сами.
Сводка для Telegram (первое сообщение) настраивается массивом `SUMMARY` рядом: `[ключ, подпись, максимальная длина]`.

> Ключи `agree`, `news`, `links`, `files`, `name`, `email` используются в коде. Если переименуете их, поправьте и обращения в `app.js`.

## Публикация на GitHub Pages
Settings → Pages → Deploy from a branch → ветка `main`, папка `/ (root)`. Если сайт лежит в подпапке репозитория (`/brief`), выберите её либо вынесите содержимое в корень.

## Проверка локально
Откройте папку любым статическим сервером, например `npx http-server . -p 5180`.
Шрифты и `localStorage` лучше проверять через сервер, а не двойным кликом по `index.html`.
